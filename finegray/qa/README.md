# finegray QA

The `finegray` QA suite covers estimation, prediction, cumulative-incidence reporting, and proportional-subdistribution-hazards diagnostics through functional, known-answer, and independent-oracle checks. Suites live in a flat `qa/` root, use one curated lane runner, and are independently runnable from this directory.

## How to run

```bash
cd finegray/qa
./run_all.sh full --source-repo "$(cd ../.. && pwd)"  # full release gate (preferred)
stata-mp -b do run_all.do quick                       # fast functional lane
stata-mp -b do test_finegray_v121.do                  # one standalone suite
```

`run_all.do` defaults to `full`; `run_all.sh` adds reliable shell exit status, provenance, receipts, and the shell-level fail-closed and transfer gates. Gate on the final `RESULT:` line or the wrapper receipt, not Stata batch mode's shell status alone.

## Isolation

The runner writes suite logs in the shared `qa/` directory, so concurrent runs of the same lane can corrupt evidence; disagreement between `run_all.log` and a suite's own log is the tell. For concurrency, copy the repository layout to a scratch tree containing both `finegray/` and sibling `tabtools/`, delete copied `qa/*.log` and `qa/run_all_status.txt`, and pass the original repository to `run_all.sh --source-repo`.

| Sibling | Required by | Behavior if absent |
|---|---|---|
| `tabtools/` | `test_finegray.do` (`regtab` integration) | Hard failure before the suite publishes a result |
| `_data/` | Repository-level example-data paths | Hard failure when an exercised example needs it |

## Conventions

- `test_*` files are functional or regression checks; `validation_*` files use hand-computable, invariant, simulated-truth, or deterministic Stata oracles; `crossval_*` files compare against independent Stata/R implementations; `benchmark_*` files measure performance and are never correctness gates.
- Every runnable suite ends with one `RESULT: <name> tests=N pass=N fail=N [skip=N]` line and exits nonzero on failure. `full` treats any skipped oracle as a failure.
- `_finegray_qa_common.do` sandboxes `PLUS` and `PERSONAL` under `c(tmpdir)` and restores them, so lane runs do not alter the user's real ado tree.
- Paths derive from `c(pwd)` or wrapper arguments; no suite depends on a machine-local absolute path.
- Test data are generated from seeded builders or downloaded through Stata's documented `webuse` examples; cross-validation fixtures are regenerated by their companion R scripts.
- Generated logs, datasets, CSV files, graphs, caches, and workbooks are gitignored. Tracked receipts and transfer pins are explicit provenance artifacts; documentation images belong under `demo/`.

## Dependencies

| Suite or lane | Needs | If missing |
|---|---|---|
| All lanes | Stata 16+ via `stata-mp` | Hard failure |
| `test_finegray.do` | Sibling `tabtools` package | Hard failure |
| `python` / `full` | `Rscript`; R packages `cmprsk`, `survival`, `riskRegression`, and `prodlim` | Hard failure; a skip cannot make the lane green |
| Optional acceleration parity | R package `fastcmprsk` | The optional comparison is omitted; core `cmprsk` parity still runs |
| Shell wrapper | POSIX shell utilities and Python 3 | Hard failure of the wrapper gate |

## Lane membership

`quick` is contained in `core`, and `core` plus the external-oracle lane forms `full`; `full` is the default release gate. The explicit per-suite lists in `run_all.do` are authoritative.

| Lane | Suites |
|---|---|
| `quick` | All curated functional/regression `test_*` suites. |
| `core` | `quick`, deterministic/known-truth validation, and native `stcrreg` prediction parity. |
| `python` | The five R-backed `crossval_*` suites; the name is retained for compatibility. |
| `full` | `core` plus `python`; default `run_all.do` and release-wrapper gate. |
| `gates` | The three multi-hour ZZF recovery, coverage, and factorization validations, run on demand. |
| Shell gates | Wrapper regression on non-`gates` lanes; stale-oracle gate on `python`/`full`; delayed-entry transfer proof on `full`/`gates`. |
| Benchmark | `benchmark_finegray_zzf.do`, run manually and never interpreted as a correctness verdict. |

## Known gaps

- `full` intentionally excludes the multi-hour `gates` lane and scaling benchmark; their separate receipts and transfer pin do not substitute for rerunning them after an estimator-core change.
