# finegray QA

archetypes: A2


The `finegray` QA suite covers estimation, prediction, cumulative-incidence reporting, and proportional-subdistribution-hazards diagnostics through functional, known-answer, and independent-oracle checks. Suites live in a flat `qa/` root, use one curated lane runner, and are independently runnable from this directory.

This file is the runbook: how to run each lane, and one sentence on what each file checks. The retrospective material — why a check exists, what it was measured at, and which defect it was written against — is in [AUDIT_NOTES.md](AUDIT_NOTES.md).

## How to run

```bash
cd finegray/qa
./run_all.sh full --source-repo "$(cd ../.. && pwd)"  # full release gate (preferred)
stata-mp -b do run_all.do quick                       # fast functional lane
stata-mp -b do test_finegray_v121.do                  # one standalone suite
```

`run_all.do` defaults to `full`; `run_all.sh` adds reliable shell exit status, provenance, receipts, and the shell-level fail-closed and transfer gates. Gate on the final `RESULT:` line or the wrapper receipt, not Stata batch mode's shell status alone.

## Isolation

The runner writes suite logs in the shared `qa/` directory, so concurrent runs of the same lane can corrupt evidence; disagreement between `run_all.log` and a suite's own log is the tell. For concurrency, copy the repository layout to a scratch tree containing both `finegray/` and sibling `tabtools/`, delete copied `qa/*.log` and `qa/run_all_status.txt`, and pass the original repository to `run_all.sh --source-repo`.

| Sibling | Required by | Behavior if absent |
|---|---|---|
| `tabtools/` | `test_finegray.do` (`regtab` integration) | Hard failure before the suite publishes a result |
| `_data/` | Repository-level example-data paths | Hard failure when an exercised example needs it |

## Conventions

- `test_*` files are functional or regression checks; `validation_*` files use hand-computable, invariant, simulated-truth, or deterministic Stata oracles; `crossval_*` files compare against independent Stata/R implementations; `benchmark_*` files measure performance and are never correctness gates.
- Every runnable suite ends with one `RESULT: <name> tests=N pass=N fail=N [skip=N]` line and exits nonzero on failure. `full` treats any skipped oracle as a failure.
- `_finegray_qa_common.do` sandboxes `PLUS` and `PERSONAL` under `c(tmpdir)` and restores them, so lane runs do not alter the user's real ado tree.
- Paths derive from `c(pwd)` or wrapper arguments; no suite depends on a machine-local absolute path.
- Test data are generated from seeded builders or downloaded through Stata's documented `webuse` examples; R cross-validation fixtures are restored from checked frozen references; companion R scripts regenerate them only on explicit request.
- Generated logs, datasets, CSV files, graphs, caches, and workbooks are gitignored. Frozen R references under `oracles/` are intentional QA fixtures; tracked receipts and transfer pins are provenance artifacts; documentation images belong under `demo/`.

## Dependencies

| Suite or lane | Needs | If missing |
|---|---|---|
| All lanes | Stata 16+ via `stata-mp` | Hard failure |
| `test_finegray.do` | Sibling `tabtools` package | Hard failure |
| `python` / `full` | `Rscript`; R packages `cmprsk`, `crrSC`, `survival`, `riskRegression`, and `prodlim` | Hard failure; a skip cannot make the lane green |
| Optional acceleration parity | R package `fastcmprsk` | The optional comparison is omitted; core `cmprsk` parity still runs |
| Shell wrapper | POSIX shell utilities and Python 3 | Hard failure of the wrapper gate |
| Every lane | **Internet access** for Stata's `webuse` datasets — `webuse hypoxia` (the shared fixture), `webuse hiv_si` (`over()` and grouped-CIF examples) and `webuse pneumonia` (the internal time-varying-covariate refusal) | `r(672)`/`r(677)` from `webuse` inside the affected suites; the failure is reported against the test, not against the network |

`webuse hypoxia` is cached at `` `c(tmpdir)'/finegray_hypoxia_cache.dta ``. Each suite that uses it defines a local `_finegray_use_hypoxia` helper (`test_finegray.do`, `test_finegray_v110.do`, `validation_finegray.do`, `crossval_finegray.do`, `crossval_cif.do`, `crossval_predict_phtest.do`, `crossval_predict_stcrreg.do`) which downloads once, `save`s the cache, and `use`s it on every later call — so a lane makes one network round trip for that dataset rather than one per suite. Deleting the cache file only costs a re-download; a stale cache cannot arise, because the dataset is a fixed StataCorp example. `webuse hiv_si` and `webuse pneumonia` are not cached and are fetched each time they are used, so those blocks need the network on every run.

### Frozen R references

Routine cross-validation restores the fixed R outputs in `qa/oracles/`; it never refits an R model. `_fg_oracle_cache.R` checks the generator source, input contents, scalar parameters, manifest checksum, and every output checksum before copying a reference to the suite's temporary output paths. Temporary input names and the replay machine's R/package versions do not change the stored numbers. Each reference records the R/package versions that generated it in `PROVENANCE.txt`.

A missing, changed, or corrupt reference fails the suite instead of silently recomputing it. Rscript still runs the replay code, so R and the listed packages remain QA dependencies. The existing stale-output checks remain active. `test_finegray_oracles.do` exercises byte-exact restoration, changed inputs/source, missing/corrupt references, and the explicit refresh path.

To deliberately regenerate references after changing a fixture or generator, run the relevant cross-validation suite with `FG_ORACLE_REFRESH=1`; inspect its numerical and provenance changes before accepting the updated references. Ordinary runs need neither a per-user cache nor a refresh. `FG_ORACLE_NOCACHE` and `FG_ORACLE_CACHE_DIR` no longer control this workflow.

## Known gaps

- **`stata-mp -b do run_all.do <lane>` does not run the three shell gates.** The fail-closed (`fg02`), wrapper-regression and delayed-entry transfer gates live in `run_all.sh`, not in `run_all.do`, so the Stata runner — and the devkit CLI, which drives `run_all.do` — reports a green lane with none of them executed. The same is true of `run_all_status.txt` when it was last written by a `run_all.sh` run: the Stata runner does not write it. **A release receipt must come from `./run_all.sh full --source-repo <git checkout>`**, run from a scratch copy, and nothing else counts as one. Without `--source-repo` the transfer gate has no git tree to extract the pinned commit from; that reports `NOT-RUN` and fails the `full` and `gates` lanes rather than passing them silently.
- `validation_variance_default_mc.do` runs only in `full` (about 3 minutes; it needs `Rscript` with `cmprsk` and `survival`), not in `quick` or `core`. After a change to the variance, the censoring weights or `strata()`/`bstrata()`, run `full` or run the file by name before quoting its numbers.
- The fit-time cached baseline and a rebuilt one differ in the last bit (relative difference at most 3.1e-16 on the lifecycle fixture), so a restored fit's `finegray_predict` is not bit-identical to the same fit's first prediction. The lifecycle blocks therefore compare two rebuilt runs, and the grid's `restore` column holds the rebuilt path to the independent oracle at 1e-10.
- The grid's nuisance cells under delayed entry and `bstrata()` have no Stata oracle for the psi term (ZZF Appendix B, Zhou et al. 4.1): they check posting (finite, symmetric, positive diagonal, different from the fixed-weight oracle), not the value; the R-backed `crossval_nuisance`/`crossval_bstrata` suites carry the value.
- **The numerical engine edits invalidate the accepted baseline calibration pin, so the edited tree has no current calibration/transfer signoff.** The sealed baseline receipt remains historical evidence. Promotion requires `./run_all.sh gates --source-repo <checkout>`, independent review of the fresh bundle, and `bash _finegray_accept_gate_bundle.sh run_status_gates.pointer`; do not update the pin to an uncalibrated engine. `receipts/` is gitignored, so an accepted bundle must be force-added for a fresh clone.
- `full` intentionally excludes the multi-hour `gates` lane and scaling benchmark; their separate receipts and transfer pin do not substitute for rerunning them after an estimator-core change.

`PWEIGHT_SCOPE.md` records a reproducible high-censoring counterexample and the precise population-interpretation boundary for pweights. Passing the recovery configuration or frozen R parity does not establish validity under general outcome-dependent sampling.

## Canonical A2 fixture adoption

`validation_fixture_recovery.do` precedes `validation_fixture_matrix.do` in quick/core/full. Four seeded recovery cases fit the genuinely proportional Fine–Gray mixture under administrative or independent random censoring. Coefficient bounds use independently fitted native stcrreg covariance for the same target (a reference-based bound, not analytic MCSE); twelve keyed CIF cells use the documented independent IPCW DGP scale. The direct suite enumerates censoring KM and retained-competitor risk weights independently, checks modified Breslow baselines, all prediction types and raw residual/time correlations, then compares aligned coefficient fits to native Stata. It covers every required A2 operator, model replay, frequency replication, design weights, cluster variance and inverse-information routes. The design-weight coefficient comparator is the independent weighted score equation with the documented unweighted censoring KM; an unaligned native stcrreg weighting convention is not treated as parity. Delayed entry is checked on the one-cause Weibull route, where the score reduces to Cox. Stratified competing-risk delayed entry and piecewise time effects remain adoption gaps; existing dedicated QA continues to cover their implementation.
