# datamap QA

The suite covers the four public commands: `datamap`, `dataprobe`, `dataqa`, and `datamvp` (`datadict`, the text layout and `format(json)` were removed in 2.0.0; the removal is pinned by `test_datamap_v200_removed.do` and `test_datamap_v200_upgrade.do`). The curated runner defaults to the full lane; every suite can also be run directly from `qa/`.

## How to run

```bash
cd datamap/qa
stata-mp -b do run_all.do
stata-mp -b do run_all.do quick
stata-mp -b do run_all.do benchmark
stata-mp -b do test_regressions.do
```

The runner reinstalls `datamap` from the package parent, redirects PLUS and PERSONAL to temporary directories, runs suites sequentially, restores the original system directories, and exits nonzero when a suite fails. Direct suite runs use their own package setup but do not inherit the runner's installation sandbox.

## Conventions

- `test_*` files contain functional and regression coverage; `validation_*` files contain hand-computable known-answer and invariant checks; `crossval_*` is reserved for an independent external implementation; `benchmark_*` is reserved for timing and is never a correctness gate.
- Every runnable suite ends with exactly one `RESULT: <name> tests=N pass=N fail=N` sentinel and exits nonzero when a check fails. The full lane permits no skips.
- `run_all.do` redirects PLUS and PERSONAL below `c(tmpdir)` before installing from the package parent, then restores both directories. After each suite it checks that `datamap.ado` still resolves inside the install sandbox; a suite that leaves it resolving elsewhere is counted as failed, and the runner restores the adopath and reinstalls `datamap` before the next suite.
- Paths derive from `c(pwd)`; no suite uses a machine-local path.
- `test_dataprobe_v1105.do` calls Stata's Python integration with `scipy` (`scipy.optimize.milp`) for its disclosure oracle, `_dataprobe_oracle_v1105.py` in this directory; without them the suite fails rather than skipping.
- Most test data are generated at runtime from built-in or seeded synthetic data; `qa/data/` holds tracked `.dta` and Markdown fixtures (`test_cohort`, `test_panel`, `test_small`, and others) that some suites read.
- Generated logs and disposable `.dta`, graph, and document outputs are gitignored; only documentation assets under `demo/` may be tracked.
- The package has no external-reference cross-validation because its deterministic maps, dictionaries, and QC summaries use hand-computable known answers and invariants as their correctness oracle.

## Evidence layers

Known-truth recovery triages datamap as N/A: every command counts, tabulates, summarizes, or compares the data it is given, and none returns an estimate whose true value a simulation could set. The Recovery cells therefore name the known-answer suites, whose truth is a hand count or Stata's own `count`, `summarize`, or `merge` on fixtures built for it.

| Route | Recovery | Reference parity | Published reproduction | Inference calibration |
|---|---|---|---|---|
| `datamap` document and `saving()` counts, shares, missing codes, and summaries | `validation_datamap_markdown_contract.do`; `validation_datamap_fixture_contract.do`; `validation_datamap_precision.do` | none: deterministic transform (each count, share, and summary is what Stata's own count, tabulate, and summarize give on the same data, then rounded and masked; the Recovery suites assert those values) | none: no grounding paper (a data dictionary and metadata table, no published method or estimand) | none: no inference reported (datamap prints and saves counts, shares, means, quantiles, and ranges, with no standard error, interval, or p-value) |
| `dataprobe` profile, gates, `diff()`, and `keyset()` preflight | `test_dataprobe_gates.do`; `test_dataprobe_v200_diff.do`; `test_dataprobe_v200.do` | none: deterministic transform (profile and gate statistics are counts, shares, and summaries of the data, and the preflight counts are those of an actual merge, which the Recovery suites run beside it) | none: no grounding paper (data checks and profiles defined by the package, no published method or estimand) | none: no inference reported (dataprobe returns counts, shares, summaries, and pass or fail verdicts, with no standard error, interval, or p-value) |
| `datamvp` missing-value patterns | `validation_datamvp.do`; `test_datamvp_oracle.do` | none: deterministic transform (pattern counts and shares are tabulations of the missing-value indicators, checked against hand counts in the Recovery suites) | none: no grounding paper (a missing-pattern tabulation, no published method or estimand) | none: no inference reported (datamvp returns pattern counts and shares, with no standard error, interval, or p-value) |
| `dataqa` ledger and register | `validation_dataqa_fixture_contract.do`; `validation_dataqa_writer_precision.do` | none: deterministic transform (the ledger records the gate results and statistics that dataprobe computed, at full precision, and masks the release cells) | none: no grounding paper (a session ledger of data checks, no published method or estimand) | none: no inference reported (dataqa stores and reports gate verdicts and statistics, with no standard error, interval, or p-value) |
